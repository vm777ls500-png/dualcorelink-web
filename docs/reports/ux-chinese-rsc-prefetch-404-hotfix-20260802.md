## Root Cause

The root cause is an Nginx publication-boundary defect.

The approved Chinese location matched only the pretty HTML route and served
`/zh/<approved-path>/index.html`. The following legacy locale regex then
captured `/zh/<approved-path>/index.txt` and returned 404. Nginx location
matching ignores query strings, so `_rsc` was not the cause.

The build generated the RSC payload, `scripts/clean-static-export.ts` retained
it, `deploy/scripts/deploy-static.sh` copied it with unrestricted `rsync`, and
the production release contained it. There was no Link path defect and no need
to disable prefetch.

## Fix

`deploy/nginx/dualcorelink.com.conf.template` now contains a second exact,
allowlisted regex for the same 12 Chinese P0 paths ending in `/index.txt`.
It appears before the legacy locale redirects and serves only the matching
file with `try_files ... =404` and the existing no-cache policy.

The rule does not include or inspect `_rsc`; Nginx correctly matches the
pathname independently of the query string. It does not create a broad
`/zh/` file allowance.

`scripts/audit-multilingual-export.ts` now requires a non-empty `index.txt` for
each released localized page and requires the per-locale RSC count to equal
the released page count. Tests verify that cleanup preserves approved Chinese
payloads, removes pending payloads, and the unrestricted release `rsync`
includes `.txt` files.
