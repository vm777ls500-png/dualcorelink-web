# Chinese Solutions, Resources, and Regions Parity Audit

Date: 2026-08-10

Production baseline: `ef730a6eca02ea851398e5f5cb2c8591bb5550a0`

Candidate branch: `hotfix/zh-solutions-resources-regions-parity-20260810`

## Scope

This audit compares the English and released Chinese listing/detail routes for:

- Solutions: 6 detail pairs and 1 listing pair
- Resources: 15 detail pairs and 1 listing pair
- Regions: 5 detail pairs and 1 listing pair

The candidate is frontend-only. It does not write WordPress, alter CMS records, change media assets, update Nginx, deploy, or update `main`.

## Production Reproduction

All six localized route families returned through `LocalizedPublicationPageView` before their specialized listing or detail renderers could execute.

## Baseline Deficits

- Content-structure affected pages: 26/26
- Image-short pages: 17/26
- Shared images absent from Chinese detail HTML: 77
- Visible section-heading deficit: 225 H2 instances
- Dedicated relationship/conversion modules absent: 71

The H2 total is the objective positive difference between each production English and Chinese detail DOM. It measures the visible structural reduction; it does not assume that every English heading needs a word-for-word Chinese equivalent.

The 71 relationship/conversion deficit is composed of six missing Solution Recommended Products modules, 60 missing Resource modules (Recommended Products, Relevant Solutions, Continue Reading, and mid-article CTA across 15 guides), and five missing Region recommendation modules.

## Root Cause

The defect is a shared rendering/composition failure, classified as B + C + D + E, with limited A:

- B: the generic localized renderer only renders common publication fields.
- C: the localized early return bypasses each specialized business renderer.
- D: relationship data is not composed into localized product, solution, resource, and region links.
- E: shared static media remains attached to the English specialized renderer and is therefore omitted in Chinese.
- A: the reviewed Chinese records intentionally consolidate editorial prose into four sections, while the English source models often use more granular sections.

The CMS data is published and usable. No CMS repair is required. The correct fix is to combine reviewed Chinese text with the immutable English structure, media, schema inputs, and relationships before invoking the existing specialized renderer.

## Implementation

`src/lib/localized-nonproduct.ts` now provides the shared composition layer:

- Chinese text overlays reviewed localized publication fields.
- Media, source structure, related entities, and schema policy remain shared.
- Internal links localize only when a released Chinese target exists.
- Pending locale routes are never generated.
- Internal query URLs are not introduced.

The three listing routes and three detail routes now retain their specialized renderers for Chinese. Shared solution media components and resource conversion components accept locale-aware labels and links. Region and listing schemas remain generated by their specialized routes.

No page is hardcoded as a standalone replacement and no media file is duplicated.

- This is a hotfix candidate only. Production remains unchanged until a separately authorized merge/deployment.
